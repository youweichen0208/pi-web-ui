# 项目与视图切换验证

2026-09-23，本机 macOS、Node 26、生产构建、Chrome headless。
测试使用独立临时工作区、agent/data 目录和空闲端口，不调用模型供应商。

`node tests/project-switch-test.mjs` 创建两个短对话（各 4 条消息）及一个长对话
（500 条消息）。浏览器链路人为延迟快照与切换确认 150ms，测量从点击到目标消息
内容进入 DOM 后的下一帧，不以项目按钮高亮作为完成。视图测量等待内容可见及两帧。

| 场景 | 实测 |
| --- | --- |
| 首次进入项目（含人为延迟） | 209.4ms |
| 缓存命中项目，20 次，P95 | 33.4ms |
| 长对话缓存回切，单次 | 35.0ms |
| 已访问终端/Git 视图，20 次，P95 | 33.4ms |

这些是当前实现的数据，首次进入与缓存命中不是修改前后的独立基线。
没有保留修改前相同环境的完整阶段计时，不能据此宣称具体提升倍数。
生产链路提供 `cwd_result.timing`（服务端开始准备、准备完成、快照发出时间），
浏览器 Performance 面板提供 `project-switch:click` 与 `project-switch:cached-content`。

验证覆盖：连续 12 次项目请求最终选择、无效目录回退、带 cwd 的文件列表、
延迟确认下缓存展示、各会话草稿、长对话滚动恢复、视图保留且只创建一次终端、
断线重连。LRU 的容量/字节预算、进行中扫描合并、过期刷新、失效防污染有单元测试。
现有协议用例另覆盖外部文件变更、后台生成持续运行、PTY 输出与输入、快照增量链。

`node tests/project-switch-electron-test.mjs` 使用临时服务数据和 Chromium profile，
验证实际 Electron 主窗口启动、Chat/Git/终端切换、xterm 实例保留。开发者工具窗口
可能先出现，测试按应用 URL 选择主窗口。

尚未形成修改前后的扫描次数统计，也未在大附件、数万条消息和真实远程网络下测量
P95。32MiB 是展示快照 JSON UTF-16 长度估算预算，不是浏览器进程总内存上限；
草稿、终端 scrollback、SDK 服务端运行时分别保留各自状态。

检查结果：协议同步、双端及测试类型检查、构建、22 个单测文件/186 项断言通过；
完整冒烟首轮的 3 个失败项修正等待条件或复跑后通过，其中后台生成、快照及外部文件变更的针对性复跑 5/5 通过。

## 补测：上一提交与当前版本对比

同机、同依赖、同固定对话数据、1440×900 Chrome headless，生产构建。旧版是提交 `aa3d48a`（0.47.6），新版是当前工作区。旧版从 git archive 提取到临时目录；未修改现有工作区。旧版不包含任务开始前已有的未提交桌面/SCM 改动，因此不是当时工作区的逐字备份。

每种条件按旧→新→新→旧（ABBA）顺序运行，以下各项每版 40 次，报告 P95。计时从点击开始，到目标消息内容可见并经过两次 requestAnimationFrame；同步完成后再进行下一次切换。与前文单次 rAF 的记录不同，两轮数字不要直接混算。

| 响应额外延迟 | 场景 | 旧版 P95 | 新版 P95 | 耗时变化 |
| --- | --- | --- | --- | --- |
| 0ms | 短对话项目回切 | 47.7ms | 48.2ms | +1.0% |
| 0ms | 长对话项目回切（500 条消息） | 64.9ms | 52.1ms | -19.7% |
| 0ms | 已访问终端/Git 视图切换 | 33.0ms | 33.1ms | +0.3% |
| 150ms | 短对话项目回切 | 197.8ms | 47.5ms | -76.0% |
| 150ms | 长对话项目回切（500 条消息） | 231.7ms | 63.7ms | -72.5% |
| 150ms | 已访问终端/Git 视图切换 | 33.5ms | 33.2ms | -0.9% |

结论：本机短对话回切和已经挂载的视图切换没有明显加速；长对话回切 P95 降低约 20%。服务端响应额外延迟 150ms 时，缓存展示绕开等待，短/长对话回切 P95 分别降低约 76%/73%。这衡量内容展示，不代表后台同步或模型生成同幅度加速。

首次访问每条件仅 2 次，不适合推断 P95：本机短对话旧 54–68ms、新 55–62ms；本机长对话旧 83–84ms、新 82–101ms，未证明首次访问稳定改善。

响应延迟模拟对所有服务端 WS 消息增加固定 150ms，保持消息顺序；不是实际远程网络的端到端测试。没有测试复杂 Git diff、真实生成中的切换或大附件。

复现：`node tests/project-switch-benchmark.mjs /path/to/built/baseline /tmp/results.json`。[完整样本与摘要](project-switch-benchmark.json)。

## 资源占用复核

在补齐查询缓存容量上限、改为缓存摘要及清理草稿缓存副本后复测。命令：
`node tests/project-switch-resources.mjs /path/to/built/baseline /tmp/resources.json`。

旧版/新版各在相同 3 个项目（含 500 条消息长对话）热身 30 次，再切换项目 300 次，
切换 Chat/终端/Git 300 次，最后空闲 10 秒。每阶段采样前显式执行垃圾回收，
使用 Chrome CDP JS 堆/DOM 计数和 Node IPC 内存、CPU 统计。结果如下：

| 最终状态 | 浏览器 JS 堆 | 服务端 RSS | 空闲浏览器主线程 | 空闲服务端 CPU |
| --- | --- | --- | --- | --- |
| 旧版 | 10.21MiB | 212.9MiB | 0.17% | 0.10% |
| 新版 | 10.68MiB | 215.0MiB | 0.11% | 0.10% |

CPU 百分比以单个核心为 100%；浏览器列只测主线程 TaskDuration，不包含 GPU、网络等进程。
JS 堆也不是浏览器/Electron 总内存。RSS 含分配器保留页，不能把小幅差异完全归因于本次改动。

新版同一个短对话界面在第 150/300 次项目切换后，GC 后 JS 堆为 8.87/8.92MiB，
DOM 节点同为 513、监听器同为 220；最后 100 次视图切换后 JS 堆从约 10.65 到 10.68MiB，
DOM 节点同为 674、监听器同为 269。未观察到明显持续攀升或 DOM/监听器积累。
这是一轮有限时长测试，不构成所有生产场景无泄漏的证明。

本轮修补：
- 服务端历史查询缓存最多保留 24 个项目，每项目最多 200 条摘要；项目查询仅保留聚合的路径/时间，避免保留 SDK `allMessagesText`。
- 草稿及附件恢复到当前输入框时从缓存移除，离开空草稿时不保留空项。未发送内容仍按会话保留，以免丢失输入。
- hook 卸载时清理待执行的快照重同步定时器。

展示缓存的 32MiB 是 JSON UTF-16 长度估算预算；JS 对象开销、临时序列化、草稿、大附件、
SDK 运行时、终端回滚缓冲都不在该预算内。访问更多不同项目、运行更多终端、积累未发送附件
仍可能提高总内存占用。本测试未覆盖数百个不同项目、大附件堆积、持续生成/终端输出及长时间 Electron 使用。

[原始采样](project-switch-resources.json)。类型检查、构建、187 项单测通过；草稿隔离、滚动恢复、重连的浏览器回归通过。
